# 扫描页文字识别：小样本对比

这 3 页的预选文字片段中，两种识别模型的检出数量相同。英文差扫描页有 1 个极浅的名称，两种模型都没有检出。

这个结果只适用于下列样本。它不是整页文字准确率，也不代表表格行列正确。

| 样本 | PP-OCRv5 server | PP-OCRv6 medium | 说明 |
| --- | ---: | ---: | --- |
| 自制中文表格页 | 14 / 14 | 14 / 14 | 14 个预选文字片段在整页输出中出现 |
| 公开英文清晰页 | 5 / 5 | 5 / 5 | 5 个预选文字片段在整页输出中出现 |
| 同一英文页的差扫描版 | 4 / 5 | 4 / 5 | 两者都漏掉颜色极浅的供应商名称 |

两种模型使用 RapidOCR 3.10.0 与 ONNX Runtime。文字检测均使用同一个 `PP-OCRv6_det_small` 模型。两次对比的图像、检测设置和预选片段完全相同。只有文字识别模型不同。

CPU 上各页单次耗时如下：v5 分别是 19.30、52.33、51.38 秒；v6 分别是 9.48、25.28、27.30 秒。计时从创建识别对象之后开始。首次识别可能还包含模型加载和预热。测试期间机器也在执行其他任务。这些数值不是稳定的速度对比。

## 样本与参考片段

- 中文页是用虚构数据生成的图片页。它包含两行商品和四列文字。预选片段为 `TEST-2026-1130`、`示例贸易有限公司`、`测试商业有限公司`、`2026-11-24`、`人民币`、`棉质布料`、`12`、`15.50`、`186.00`、`包装纸箱`、`25`、`2.20`、`55.00`、`241.00`。
- 英文页来自 [InvoiceOCR-Synth](https://huggingface.co/datasets/alamgirqazi/invoice-ocr-synthetic)。作者为 Alamgir Munir Qazi、Jamal Abdul Nasir、Pratheesh Chambeth 和 Waqar Shahid Qureshi。数据集使用 CC BY 4.0，内容为虚构单据。[项目说明和许可](https://github.com/alamgirqazi/synthetic-invoice-gen#licence)。
- 两个英文版本对应同一份单据。预选片段是单号 `INV-20230715-001`、供应商 `Eventful Ticketing Inc.`，以及前三条商品名称 `General Admission Adult`、`General Admission Child`、`VIP Adult`。数据集的 train 分区中，清晰版行号为 0，差扫描版行号为 1876。

中文参考内容来自制图时写入的文本。英文参考内容来自数据集提供的字段。为了比较，脚本统一忽略英文大小写、空白和标点，再检查片段是否出现在整页识别文本中。

这个方法可能因为文本出现在错误位置而计为检出。它也无法发现额外识别出的错误文字。数字中的小数点或连字符错误也可能被忽略。结果不检验内容与行、列的对应关系。

## 限制

- OCR 是图像文字识别。对比直接输入页图，未覆盖 PDF 文件打开、页面渲染或最终 Excel 导出的全过程。
- 中文样本是清晰的自制图片，并非真实扫描票据。英文样本是合成单据，不代表真实客户单据。
- 样本只覆盖 2 份不同内容，其中一份有两种图像质量。没有覆盖手写、印章遮挡、长文档和多语言混排。
- 中文表格的 14 个片段只检验文字是否出现。表格结构、单元格归属及漏掉的整行需另行核对。
- 两种模型共用检测模型，因此这不是两个完整 OCR 引擎的全面比较，也不能说明任一模型整体更准确。

## 复现

将 `ocr_public_benchmark.py` 与 `ocr_compare_models.py` 放在同一目录，使用 Python 3.12 和项目的 `requirements.txt` 安装依赖。将这两个 RapidOCR ONNX 识别模型放在脚本同目录的 `ocr_models` 文件夹：

- [PP-OCRv5 server](https://www.modelscope.cn/models/RapidAI/RapidOCR/resolve/v3.10.0/onnx/PP-OCRv5/rec/ch_PP-OCRv5_rec_server.onnx)
- [PP-OCRv6 medium](https://www.modelscope.cn/models/RapidAI/RapidOCR/resolve/v3.10.0/onnx/PP-OCRv6/rec/PP-OCRv6_rec_medium.onnx)

检测模型使用 RapidOCR 安装目录中自带的 `PP-OCRv6_det_small.onnx`。脚本生成中文样本时使用 Windows 自带的微软雅黑字体。第三方模型的使用和再分发需遵循各自的许可。

```powershell
python ocr_public_benchmark.py
python ocr_compare_models.py
```

第一条命令下载 3 份公开单据的清晰版与差扫描版，并生成 1 份中文样本。第二条只对其中 3 页运行比较，并在 `ocr_benchmark_public/ocr_compare.json` 保存各项结果。首次下载需要网络；识别过程在本机完成。个别 Windows 环境可能需要先安装兼容的 Microsoft Visual C++ 运行库。

如遇本机运行库冲突，可以将环境变量 `OCR_MSVC_DLL` 指向已合法取得的兼容 `msvcp140.dll`，再执行第二条命令。测试图片和结果不需要上传公开仓库。
